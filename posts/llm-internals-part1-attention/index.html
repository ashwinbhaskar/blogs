Inside an autoregressive LLM

Part 1: The attention block

How a token finds out what the other tokens are saying: one matrix at a time, asking why at every step.

Before we start

The three words in the title

LLM stands for large language model; autoregressive says how it writes.

Language model (the LM)

A program that, given some text, returns a probability for what comes next. It is made by training: reading a huge amount of text and nudging the program's numbers, again and again, so that its guesses about the next token (a word, or a piece of one; slide ) get better.

Large (the first L)

The numbers are the parameters, or learned numbers, of a neural network: one big function built mostly from matrix multiplications, with every entry of every matrix adjustable. GPT-2 small (2019) has 124 million of them; LLaMA-2 7B has 7 billion; the largest today have hundreds of billions.

Autoregressive

It writes one token at a time, and each new token is predicted from everything written so far, its own earlier output included. Auto: its own; regressive: predicting from the past. The next slide shows the loop; the one after places this kind of model among its relatives.

Before we start

A language model guesses the next token

Feed it text and it returns a probability for every possible next token. Above: GPT-2 small, given this sentence without its last word, bets on too, so, trying. (hungry is 13th, at 0.9%.)

This series opens that transformer box. Part 1 takes one of the two blocks inside its repeated layer (picture on slide ).

Pick one, append it, run again. That loop is “autoregressive” in action: each new token is predicted from the text so far, the model's own picks included. A chat reply is this loop run a few hundred times.

The network inside the box is a transformer, the design from 2017 that nearly every language model now uses.

Before we start

Where this kind of model sits in the family

Encoder-only

BERT (2018). An encoder is a network that reads: the whole text at once, every token looking at every other, before and after. Good at labelling and search; it does not write text.

Encoder-decoder

The original 2017 transformer. An encoder reads the input, then a decoder, a second network, writes the output. Built for translation.

Decoder-only, autoregressive

GPT, LLaMA, and the chat assistants built on models like them. One network both reads and writes; each token may look only at itself and the tokens before it. This is what “LLM” usually means today, and what this series is about.

All three share the attention block we are about to build. What lets ours run the loop honestly is one line inside it, the mask, which arrives on slide .

The big picture

From text to numbers: tokens and embeddings

A tokenizer chops text into pieces from a fixed vocabulary (GPT-2 has 50,257). Common words are one piece; rare ones are split: un|bel|iev|ably. Each piece is a token and gets an id.

Each id picks a row of an embedding table E. Nobody designs the rows: they start random and are adjusted by training until tokens used in similar ways sit close together. Stack our nine rows, add position information (GPT-2 does it here), and that is X.

The big picture

The whole transformer, zoomed out

Text goes in on the left, next-token probabilities come out on the right, and in between the same layer is repeated N times: GPT-2 small stacks 12, LLaMA-2 7B stacks 32. Each layer is two blocks: attention, then MLP.

This deck: the attention block. Part 2 takes the MLP block, Part 3 follows a token up through the layers, Part 4 covers the LM head (no relation to the attention heads inside the block) that turns the last vector into probabilities.

The big picture

Zooming in: one layer, two blocks

Attention block: the tokens exchange information. It is the only place in the whole model where one token's vector can influence another's.

MLP block: each token is transformed on its own, without looking at the others. (Part 2.)

In one sentence: attention is the step where every token gathers information from itself and the tokens before it, weighted by how relevant each of them looks. The rest of this deck is that sentence, made precise.

Heads: the attention block runs h copies of everything that follows, side by side, each in a narrower width dk. We build one head first (Stops 1 to 4) and combine them at Stop 5.

Order-blind. Nothing we build from here knows that cat comes before chased. Position is injected either here (GPT-2 adds a position vector to each row of X) or later, inside attention (LLaMA rotates the Q and K we build next: RoPE). That one sentence is all we say about it today.

Stop 1: Setup

Every token asks three questions

Query  Q

“What am I looking for?”

Key  K

“What do I have to offer?”

Value  V

“What do I give if picked?”

A library: your search phrase is the query, the label on each spine is a key, the book itself is the value. Matching query against keys tells you which books to pull; the values are what you actually read.

All three are the same row of X seen through three learned lenses: Wq, Wk, Wv.

Stop 2 will dot each token's query with every token's key. Why not dot rows of X with each other directly? Because then “what I look for” and “what I offer” would have to be the same vector. Wq and Wk let them differ.

Stop 1: Setup

Making Q for one head

Each head owns its own Wq, Wk, Wv, each of shape [d_model × d_k]. The same recipe gives K and V.

Row i of Q is token i's question, compressed from dmodel down to dk numbers. In GPT-2 small: 768 → 64, twelve times over.

Stop 1: Setup

The packing trick: all heads in one multiplication

Drawn with 3 heads for space; GPT-2 small has 12.

Column j of the result is X · (column j of W). It never touches any other column, so each head's result lands in its own columns: no cross-contamination.

So h small multiplications become one [L × d_model]·[d_model × d_model]. Same maths, one call. The heads' work is independent, so it can be packed into the one big matrix multiplication GPUs are built for.

GPT-2 goes one step further and packs Q, K and V together: a single 768 × 2304 matrix (called c_attn in the released parameters), then splits the result three ways.

2

Scores

One number for every pair of tokens: S = Q·KT

Stop 2: Scores

The scores are S = Q·KT. Why the transpose?

We want an L × L table, call it S, where cell (i, j) = qi · kj: every query dotted with every key.

A matrix product computes row of the left · column of the right. Queries already sit in rows.

So keys must be arranged as columns. That is the entire reason for the transpose: it puts each kj where the multiplication will find it. Row i meets column j at cell (i, j).

Stop 2: Scores

The scores: every token against every token

A dot product is a similarity meter:

  • vectors pointing the same way → large positive
  • unrelated (orthogonal) → near zero
  • pointing opposite ways → large negative

Cell (i, j) is not “how much i attends to j” yet. It is “how well what i wants lines up with what j offers”. Stop 3 turns alignment into a share.

Look at row it: the two nouns score highest. Toy numbers, but the shape of the idea is right.

Toy example: dk = 2, matrices chosen so the arithmetic is checkable by hand. Raw products qi · kj, nothing applied yet. We follow row it to the end on slide .

Stop 2: Scores

The packing trick breaks here

Could we score in one shot with the packed [Q1|Q2|Q3] and [K1|K2|K3]?

A product sums over the shared dimension, and the shared dimension now runs across heads. The heads' tables get added together. Exactly what we do not want.

So this step stays separate: h independent [L × d_k]·[d_k × L] products, computed together as a batch of shape h × [L × L]. Independent work that cannot be merged into one.

Stop 2: Scores

…then × h heads × N layers, every time the model runs (one “forward pass”).

Double the context, quadruple the work (and the memory for the table).

That is why long context is expensive, why a technique called FlashAttention avoids ever writing the full table out, and why so much research goes into cheaper substitutes for this one multiplication.

3

Weights

Three steps turn scores into weights: divide by √dk, mask the future, softmax

Stop 3: Weights

Softmax: a budget of exactly 1

The recipe, in running order: divide by √dk → mask the future → softmax. We explain softmax first (the goal), then the two preparations.

Aij=eSijΣm eSim

Softmax turns each row of scores into shares that sum to 1. Call the result A: token i now has a budget of exactly one unit to spend across the tokens it looks at. That is an attention weight.

Why ex rather than dividing by the row sum? Scores can be negative. The exponential makes everything positive, keeps the order, and stretches gaps: a score higher by 2 gets e² ≈ 7.4× the share.

Row it, raw scores. Still off: the spread (next slide) and the future (the slide after).

Stop 3: Weights

Step 1 of the recipe: divide by √dk. Why?

q · k is a sum of dk products. If the entries are of size about 1, the sum's spread (its standard deviation; the dk variances add up) grows like √dk. With dk = 64, raw scores come out ×8 too wide.

Softmax stretches gaps exponentially, so scores spread by ±8 give one token essentially the whole budget and the rest nothing. Nothing can be learned from the ones that got nothing (learned during training, which we skip). Divide by √dk and the spread is back to ~1: softmax stays soft, and learning can proceed. (Row it: cat's share drops from .264 to .217 and the others gain.)

From here on, S means Q·KT / √dk.

Stop 3: Weights

Something is wrong.

Step 2 of the recipe: the causal mask.

Token 3, chased, has been reading token 8, was. For a model whose entire job is predict the next token, that is cheating: the answer is sitting on the table.

Every cell above the diagonal is a peek into the future. Fix: before the softmax, set every cell with j > i to −∞. Since e−∞ = 0, those cells get exactly zero budget.

The causal mask. The table turns lower-triangular and each row's shares are recomputed over the past only. This one line is what makes the model autoregressive.

Stop 3: Weights

What the mask buys us

Training: L exercises in one pass

Token 1 guesses token 2, token 2 guesses token 3, … all at once, in a single forward pass, and nobody can peek. Every position is a practice question, and that is how an LLM is trained.

Proof it works: GPT-2 small, layer 4 head 3, row it

Identical to every decimal. When the model processes it, the word that would disambiguate it has not been written yet.

Using the trained model (inference): nothing in the past ever changes

A token's key and value never depend on later tokens, so they can be computed once and cached. Generating the next token only needs one new row: the KV cache. (Part 3.)

4

Values

Z = A·V: a weighted average of the value rows

Stop 4: Values

Multiply by V: a weighted average

zi=Σj Aij vj

Call the result Z. Row i of Z is a blend of value vectors, weighted by row i's budget. Token it's new vector is mostly what cat and mouse handed over. The information has moved.

Z has one row per token, dk wide. Shapes: [L × L]·[L × d_k] → [L × d_k]. No transpose this time: V's rows are already tokens, which is exactly what the columns of A index.

Stop 4: Values

Follow one token all the way through

Toy numbers, head 1, dk = 2, qit = [−0.92, 0.46]. Every number below is reproducible by hand.

Sum of the last column: zit = [−0.49, 0.03], the new 2-number summary of it from this head. Real models do this in 64 or 128 dimensions, but the arithmetic is the same.

Heads and the residual stream

Putting the picture back together

Stop 5: Heads

One head, one pattern

Each head has its own lenses Wq, Wk, Wv, so each learns its own way of relating tokens: “the token before me”, “the nouns so far”, … A sentence needs several of these at once. The odd one out on the right is not broken. Watch.

All three are GPT-2 small on our sentence. Layer 4 head 11 puts 0.99+ on the previous token at every position after the first.

Stop 5: Heads

The idle head wakes up

Layer 5, head 1, on the sentence written twice. Hover a cell for its value.

First copy of the sentence: everything lands on The. With nothing useful to do, the head parks its budget on the first token (an attention sink: what column 1 was absorbing earlier).

Second copy: each token looks at the token that followed its previous occurrence: because → it, it → was. It is predicting by copying.

An induction head: a mechanism behind in-context learning (learning a pattern from the text, with no extra training), in a 2019 model with 124 million learned numbers.

Stop 5: Heads

Bring the heads back together

Drawn with 3 heads for space; GPT-2 small has 12.

Concatenation only lays the heads side by side; nothing has mixed yet. Wo, a fourth learned matrix of shape [d_model × d_model], is where the heads talk to each other.

Split Wo into row-blocks and the product is Z1·Wo1 + Z2·Wo2 + Z3·Wo3, one term per head: each head writes its own additive update. Packing is safe again, because adding the heads together is exactly what we want here.

Stop 5: The residual stream

Add, don't replace

X←X+Attention(LN(X))

LN is LayerNorm, the same kind of “norm (LN)” box as in the zoomed-out picture: a per-token rescaling. Every block has one on its way in, and there is a final one before the LM head. Strictly, Stop 1 should have read Q = LN(X)·Wq; we left it out until now because it changes nothing in the story. GPT-2 and LLaMA both normalise before each block (LLaMA uses the RMSNorm variant). That is all we say about LN.

X is a running scratchpad, the residual stream. The attention block reads it, computes an update of shape [L × d_model], and adds it back. What a token already knew is never thrown away: a block only adds a correction, and a block with nothing to say adds nothing. Every block after this one, in this layer and the next, reads the same stream.

Stop 5: The whole attention block

The whole attention block: pack, split, pack

LN on the way in is omitted from the picture.

Q, K, V can be packed because each head's result stays in its own columns. The scores cannot, because packing would add the heads' tables together. Wo can be packed again because there, adding the heads together is the point. Knowing which is which is most of what “multi-head” means in practice.

Recap

The whys, in one place

  • Why transpose K? A matrix product dots rows with columns; keys must become columns.
  • Why softmax? Negative scores → positive shares that sum to 1: a budget.
  • Why ÷√dk? Keep the score spread ~1 so softmax stays soft and every token can still be learned from.
  • Why the mask? No peeking at the future; L prediction exercises per pass.
  • Why many heads? One head = one pattern; a sentence needs several at once.
  • Why pack Q/K/V and Wo but not the scores? Packing sums over the shared dimension: harmless for Q, K, V, fatal for the scores, wanted for Wo.
  • Why Wo? Concatenation doesn't mix heads; Wo does.
  • Why add to X? Nothing a token knew is thrown away; each block adds a correction, and can add nothing.

End of Part 1

Attention moves information between tokens.

Every token's new vector is a blend of what other tokens handed over. But notice what did not happen: apart from the linear lenses, no token changed its own features. Everything else was mixing.

Transforming a token's own features is the MLP's job. → Part 2.
