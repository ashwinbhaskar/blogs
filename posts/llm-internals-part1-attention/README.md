# Inside an Autoregressive LLM, Part 1: The attention block

A single-file, dependency-free HTML slide deck (32 slides). It assumes the series Introduction (a separate deck in `posts/llm-internals-intro/`: what a language model is, the next-token loop, the model family, tokens and embeddings, the whole transformer), recaps the one picture it needs (one layer, two blocks), then builds the attention block one matrix at a time, using one running sentence (*The cat chased the mouse because it was hungry*) and real attention patterns from GPT-2 small. Every section divider carries a "you are here" strip that places the current stop inside the attention block and the block inside the model.

`index.html` is the whole deck: HTML, CSS, JavaScript and data in one file. No build step, no framework. Open it in a browser or host it anywhere static files are served.

## Where it lives

This folder is one post of the site in the repository root: `post.json` holds the title, date, tags and series
entry that the home page reads, and the build copies the folder to `/blogs/posts/llm-internals-part1-attention/`
as-is. The root README describes the whole process (new posts, preview, deploy). Deep links work:
`.../#/16` opens slide 16, `#/16/2` opens it with two build steps already revealed. The small "All posts" link at
the top left of the deck goes back to the home page.

## Editing the deck

Everything lives in `index.html`, top to bottom: `<style>`, then one `<section>` per slide inside `#deck`, then a `<script>` with the data, the diagram helpers, and the ~80-line slide engine.

**Add a slide.** Copy any `<section>…</section>` and place it where it belongs in the order. The counter, progress bar and hash links update automatically. Use `class="divider"` for a section-break slide and `class="title"` for a title-style slide.

**Build steps.** Any element with `class="frag"` is hidden until the presenter advances. Steps reveal in document order; add `data-order="2"` to override. A fragment can also switch something on when it appears: `data-target="#some-svg .hl-row"` adds the class `on` to whatever matches (a comma-separated selector list works too). That one mechanism drives everything that is not a plain reveal: `.hl` highlight overlays in the diagrams are hidden until they get `on`; `.fade` elements disappear when they get `on`; the numeric walkthrough table reveals its column groups because empty `<span class="frag">` elements target `.g1` to `.g4`; and the reveal slide swaps its headline because the last fragment targets `.h-swap`. Print mode shows every step expanded.

**Cross-references and locators.** To refer to another slide by number, give that slide's `<section>` an `id` and write `<span class="ref" data-ref="that-id"></span>`; the number is filled in at load time, so inserting slides never leaves stale references. A `<div class="locator" data-stage="scores"></div>` renders the "you are here" strip (stages: `qkv`, `scores`, `weights`, `values`, `heads`, `mlp`).

**Diagrams.** Matrix pictures are generated by one of two helpers in the script:

- `matrix({...})` draws one bracketed matrix: dots (`dots:true`) or values (`vals`, `color`, `text`), row/column dimension labels, token labels, coloured head-blocks, causal `mask:true`, and highlight overlays (`hl: [{type:'row', i:6, cls:'hl-row'}]`).
- `line([A, {op:'·'}, B, {op:'='}, C])` lays matrices and operators out on one line and returns an `<svg>` scaled to fit.

Look at the `// 5 · X · Wq = Q` block for the smallest example and copy from there. Colours are in the `C` object and the CSS `:root` variables; sequential heat-map colour is `SEQ`, the signed-score palette is `DIV`.

**Data.** `TOY` holds the hand-checkable example (d_model = 4, h = 2, d_k = 2): the input `X`, the weight matrices, `Q`, `K`, `V`, raw and scaled scores `S_raw`/`S`, the attention matrices `A_unmasked`/`A`, and the output `O`. `REAL` holds GPT-2 small attention matrices for layer 4 head 3, layer 4 head 11 and layer 5 head 1 on the sentence, plus layer 5 head 1 on the sentence repeated twice (the induction-head slide). Values are rounded to three decimals.

## Where the real numbers come from

The GPT-2 matrices (and the Introduction deck's token ids, next-token probabilities and embedding row) were produced with a plain-numpy forward pass of GPT-2 small (124M); see `tools/gpt2_attention_numpy.py`, which reads the weights from the ONNX Model Zoo copy of GPT-2 and the original BPE tokenizer files. The same numbers come out of the standard route, which is the easier one if you want to try other sentences or models:

```python
from transformers import GPT2TokenizerFast, GPT2LMHeadModel
tok = GPT2TokenizerFast.from_pretrained("gpt2")
model = GPT2LMHeadModel.from_pretrained("gpt2", attn_implementation="eager").eval()
enc = tok("The cat chased the mouse because it was hungry", return_tensors="pt")
out = model(**enc, output_attentions=True)
A = out.attentions[4][0, 3].detach().numpy()   # layer 4, head 3: an L×L matrix, rows sum to 1
tokens = tok.convert_ids_to_tokens(enc.input_ids[0])
```

The deck went through two review loops before this version: seven rounds with a general reviewer (clarity, consistency, simplicity, completeness, interactiveness), then five rounds read in strict slide order by a reviewer playing a second-year CS student with no ML background, whose job was to flag anything used before it was introduced (the last two rounds on the new opening). Vocabulary is deliberately one word per thing: a *layer* is the unit repeated N times; its two halves are the attention *block* and the MLP *block*; *weights* only ever means the attention weights A; the W matrices are *matrices* or *learned numbers*; *lenses* means W_q, W_k, W_v.

Three facts the deck relies on, all reproducible this way: the *it* row is identical whether the sentence ends in *hungry* or *tasty* (causal mask); layer 4 head 11 puts ≥ 0.99 on the previous token at every position after the first; layer 5 head 1 sits on the first token until the text repeats and then attends to the token after each earlier occurrence.
